# 系统测试计划：本地独立双人分工 v1.1

## 适用方式

两人居家办公，各自本机Tomcat + Spring Boot + SQLite独立测试。无远程连接、无共享数据库、无现场协作、无组长、无具体时间安排。此版本替代v1.0的共同服务与双人配合要求，保留旧文件作历史记录。

## 分工

| 人员 | 独立测试内容 | 数量 |
|---|---|---|
| A | 注册登录、首页、二手交易、商品审核与媒体评论、商品与账号异常、并发购买、Chrome | 28项 |
| B | 会话失效、跑腿、个人空间、管理员用户管理、任务审核与媒体评论、任务与管理异常、并发接单、Edge | 28项 |
| 每人各自完成 | 本机启动、资源更新、重启持久化、本人模块最终回归 | 每人4项 |

每人32项，按复杂度尽量平衡；两条交易主流程分别归一人独立完成。不能只按测试条数理解工作量，相似终止分支和媒体场景已对称分配。

## 环境基线

两人拿同一份已包含修复的代码、app-test-baseline.db和测试uploads目录，各自备份原库后放入本机运行路径。路径不要求相同，CTCP_DB_PATH/CTCP_UPLOAD_DIR如已设置必须指向本机文件。默认路径为backend/db/app.db和uploads。不要直接复制别人的IDEA workspace.xml或带绝对路径的配置。

已有测试账号admin，u1/u2/u3，登录信息见测试数据库使用与恢复说明。自己使用隔离浏览器配置扮演全部角色；退出旧登录后开始。图片使用本机localhost:8081，保留测试图片子目录。基础数据副本相同，执行后各自独立变化，不同步数据库。

本地离线不影响HTTP localhost访问。预先准备JDK、Tomcat、Node、Python及后端构建依赖；缺少依赖记录环境阻塞，不把网络安装作为必测前置步骤。

## 执行与交付

分别打开本目录本地独立测试任务-A-v1.1-2026-09-08.md和B文件。按环境、正常闭环、状态分支、异常、并发、兼容性、复测推进。每人自行审核自己负责模块内容。

本机并发使用两个登录会话并行请求，不依赖另一人。无法并行发起时标记阻塞。故障场景仅停止自己的测试服务。

各人交付本人填写的32项记录、缺陷和证据，后续异步汇总即可，无需实时会合。跨机器资源ID可能相同，证据必须标A/B来源。共有60个唯一用例，四个环境/最终回归用例各测两次，因此合计64条执行记录。

各自复测修复并记录版本。总体通过要求两份记录完整、所有必测通过且无未解决缺陷；有条件通过要求全部执行、P0/P1清零且仅剩影响明确的P2/P3；核心、权限或并发未完成或存在P0/P1则不通过。未开始时记测试进行中，不提前给验收结论。

本次仅修订测试安排，未重新执行系统测试，也未改动数据库或业务实现。历史自动化结果不能代替两台机器本轮验证。
