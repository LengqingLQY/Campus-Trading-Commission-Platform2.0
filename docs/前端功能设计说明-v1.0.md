## 1. 页面与脚本对应

| 页面 | 脚本 | 主要职责 |
|---|---|---|
| `index.jsp` | `api.js`、`auth.js` | 登录、记住账号、错误提示、登录后跳转 |
| `register.jsp` | `api.js`、`auth.js` | 注册字段校验、可选联系方式、成功后返回登录 |
| `main.jsp` | `api.js`、`domain.js`、`home.js` | 随机推荐流、买卖交易待办 |
| `secondhand.jsp` | `api.js`、`market.js` | 商品搜索、排序、分类、动态列表 |
| `product-detail.jsp` | `api.js`、`product-detail.js` | 商品详情、身份判断、购买、进入订单 |
| `product-publish.jsp` | `api.js`、`product-publish.js` | 商品发布、实时预览、表单校验 |
| `product-order.jsp` | `api.js`、`domain.js`、`product-order.js` | 买卖双方订单详情、卖家交付、买家确认 |

`api.js` 是统一前端基础层，负责：

- 默认连接 `http://localhost:8081/api`；当页面本身运行在 8081 时自动使用同源地址；
- 所有请求携带 `credentials: include`，支持 `JSESSIONID`；
- 同时识别正确 HTTP 错误状态和旧骨架可能返回的 `HTTP 200 + code!=0`；
- 统一登录态、按钮加载态、错误提示、Toast 和输出转义。

`domain.js` 保存无 DOM 依赖的推荐抽样、待办分类和订单动作规则，并由 `web/tests/frontend-contract.test.js` 直接验证，避免页面展示规则与接口契约漂移。

## 2. 发现首页

### 2.1 推荐流

首页不是固定横幅，而是类似购物应用的发现流：

1. 并行读取 `GET /api/public/products?page=1&size=50` 和 `GET /api/public/tasks?page=1&size=50`；
2. 只保留 `product.status='on_sale'` 与 `task.status='open'`；
3. 商品池与任务池分别随机打散，优先抽取最多 5 件商品和 3 个任务，确保两类推广都有曝光；一类数据不足时由另一类补齐；
4. 合并后再次使用 Fisher–Yates 算法打散，每次展示最多 8 张卡片；进入页面和点击“换一批”都会重新随机；
5. 商品卡片跳转 `product-detail.jsp?productId={id}`；
6. 跑腿卡片跳转现有 `task-detail.jsp?taskId={id}`。

推荐只改变展示顺序，不修改任何后端数据。搜索仍由二手交易页承担。

### 2.2 右侧交易待办

首页并行读取：

- `GET /api/me/products?type=published&page=1&size=50`；
- `GET /api/me/products?type=bought&page=1&size=50`。

只显示 `orderStatus` 为 `created` 或 `delivered` 的进行中订单，并按“当前用户需要操作”优先排序：

| 用户身份 | 状态 | 待办文字 | 是否优先 |
|---|---|---|:---:|
| 卖家 | `created` | 待交付 | 是 |
| 买家 | `created` | 待卖家交付 | 否 |
| 卖家 | `delivered` | 待买家确认 | 否 |
| 买家 | `delivered` | 待确认收货 | 是 |

点击待办统一进入 `product-order.jsp?orderId={orderId}`。角色只用于前端导航提示，真实权限由订单详情接口根据 session 返回的 `viewerRole` 决定。

## 3. 二手交易流程

```text
商品列表 → 商品详情 → 立即购买 → 交易页
                                  │
               卖家确认交付 ──────┤
                                  ▼
                           买家确认收货 → 完成
```

### 3.1 购买前

- 游客可浏览列表和详情，购买按钮引导登录并携带安全的 `next` 页面参数；
- 卖家查看自己商品时不能购买；
- 已售出或已完成的商品不显示购买按钮；
- 购买前使用确认对话框明确说明“不含在线支付、线下交接”。

### 3.2 购买后

- `POST /api/products/{id}/buy` 成功后使用响应中的 `orderId` 进入订单页；
- 订单页通过 `GET /api/product-orders/{id}` 获取角色、状态、成交价快照和交易双方联系方式；
- 卖家仅在 `created` 状态看到“确认商品已交付”；
- 买家仅在 `delivered` 状态看到“确认收到商品”；
- `completed` 状态只读展示完成结果；
- 非交易参与者访问由后端返回 `403`，前端显示无权限提示。

## 4. 表单与显示规则

- 注册密码至少 6 位，确认密码和使用规范勾选只在前端校验；
- “记住我”只保存校园账号到 `localStorage`，不保存密码和长期登录凭证；
- 商品发布按接口契约直接成为 `approved + on_sale`，页面不再显示“提交审核”；
- 金额统一显示两位小数；枚举英文码只在接口传输，页面统一映射中文；
- 用户输入经 HTML 转义后再进入动态模板，避免标题或描述注入脚本。

## 5. 状态与异常体验

- 所有异步区域都有加载态、空状态和错误状态；
- 提交按钮请求期间禁用，避免重复登录、重复发布或重复购买；
- `401` 自动跳转登录页并保留当前业务页面；
- `409` 直接展示服务端冲突原因，例如商品已售出或订单状态已变化；
- 主界面推荐接口和待办接口独立容错，一侧失败不影响另一侧可用内容。

## 6. 后端联调前提

现有后端骨架尚未覆盖全部接口。前端完成后可直接按《接口契约》v1.1 联调，其中二手订单新增接口和数据库迁移要求详见《前端新增接口协议-二手交易闭环-v1.1》；前端不包含任何后端实现。
