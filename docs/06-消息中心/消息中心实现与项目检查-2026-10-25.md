## 本轮完成

- 新增 NotificationController、NotificationService、NotificationDAO 和返回 DTO，按当前 session 隔离消息。管理员也只读取自己的消息。
- 完成四个接口：消息分页、全局未读数、单条已读、按 upToId 水位全部已读。严格校验分类、状态、分页、消息 ID 和 JSON 整数水位。重复已读保留第一次时间，他人消息与不存在消息统一返回 404。
- 新增 notification 表、时间索引和未读部分索引；同步 Spring 启动迁移、Python 迁移、全新库 schema、初始化删除顺序。
- 审核结果实际变化、购买/接取、交付/送达、订单完成、终止申请发起/撤回/拒绝/同意均生成消息。消息保存标题和正文快照，订单目标保存当次订单 ID，完成事件通知双方评价。
- 消息写入和业务变更在同一事务内，任一消息写入失败全部回滚；相同审核不重复发消息，失败或重复业务操作不新增消息。不补发上线前历史消息。
- 修复跑腿待处理终止申请未阻止送达/完成的问题，以及跑腿和二手订单更新后未检查资源状态更新是否成功的问题；并发接单采用条件更新先获取 SQLite 写锁，避免读后升级写锁冲突。
- 跑腿公开详情不再向游客或无关用户返回终止申请理由。
- 修复消息页快速筛选时旧响应覆盖、仅未读末页清空后无法回退、首次列表未同步水位和角标、标记已读后顶部数量过期的问题。全部已读使用成功加载的列表水位，保留之后到达的新消息。
- 访客不请求消息接口、不启动消息轮询；隐藏页面暂停轮询，重新可见后刷新；登录过期清理角标和定时器；网络错误保留上次数字，下次刷新重试。
- 两类订单加载失败时保留返回消息中心入口；跑腿进入任务处理时携带原订单返回地址，已终止订单仍不提供新一轮任务处理入口。

## 数据库升级与启动

已有数据库可在后端启动时自动执行 001-rating.sql、002-notification.sql，也可以在仓库根目录运行：

```powershell
python backend/db/migrate_db.py --db '实际已有数据库路径'
```

迁移只增加表和索引，保留账号、订单及评价，支持重复执行。迁移后消息表初始为空。本轮测试只使用临时库，没有修改用户业务库。

全新环境先使用 backend/db/init_db.py 创建基础表和演示数据，再启动后端。该初始化脚本会重建数据库，已有库升级使用 migrate_db.py。

项目要求 Java 23；本机默认 java 指向 Java 8，本轮显式选择已安装的 JDK 23 构建。仓库根目录执行：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-23'
.\mvnw.cmd package
node --test web/tests/*.test.js
python backend/db/test_db.py
python backend/db/test_migrations.py
```

后端产物为 backend-java/target/campus-errand-backend-1.0-SNAPSHOT.jar，前端为 web/target/CTCP.war。按[构建与打包说明](../04-联调测试与交付/构建与打包说明-v1.0-2026-09-07.md)部署。

## 由用户手动验收

请部署最新 JAR/WAR 后，在浏览器完成以下检查：

1. 用管理员审核商品和任务，再用发布者查看通知；重复同一审核不新增消息，驳回理由完整显示。
2. 分别走商品购买→交付→完成、跑腿接取→送达→完成；确认接收人、角标、订单编号正确，完成后双方可进入评价。
3. 两类订单互换双方身份发起、撤回、拒绝、同意终止；有待处理申请时不能推进。终止后重新成交，旧通知仍打开原订单，旧跑腿订单不出现“进入任务处理”。
4. 消息超过一页时切换分类和仅未读，读完最后一页、返回消息列表，检查页码回退、筛选保留及数量同步。
5. 点击全部已读期间由另一账号触发新通知，确认新消息仍未读；切换标签页后回到消息页，确认角标刷新且列表用提示刷新。
6. 暂时断网后重试；用小窗口及键盘检查长正文、按钮焦点和布局。目标不可访问时仍可读消息正文并返回消息中心。

真实浏览器布局、跨端口 session/cookie 和部署后的交互仍以以上手动验收结果为准。
