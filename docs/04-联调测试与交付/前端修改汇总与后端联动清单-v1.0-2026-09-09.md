#### 3.1.3 跑腿待办状态映射（前端已实现）

前端 `buildTaskTodos()` 函数按以下规则生成待办项：

| 角色 | 任务状态 | 显示状态 | 是否需要操作 |
|------|---------|---------|-------------|
| 发布者 | `accepted` | 等待送达 | ❌ 等待接取者送达 |
| 发布者 | `delivered` | 待确认 | ✅ 点击确认完成 |
| 接取者 | `accepted` | 待送达 | ✅ 点击标记送达 |
| 接取者 | `delivered` | 已送达 | ❌ 等待发布者确认 |

- `open`、`completed` 状态不进入待办列表。
- 待办项点击后跳转至 `task-detail.jsp?taskId=${task.id}`。

**当前状态**：✅ 已实现（commit d122657）

#### 3.2.2 修改接口：公开任务详情

```http
GET /api/public/tasks/{taskId}
```

**认证**：可选

**路径参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `taskId` | integer | 任务 ID |

**权限逻辑修改**：

```
IF task.auditStatus = 'approved' THEN
    → 返回完整任务详情（所有人可见，原有逻辑不变）
ELSE IF task.auditStatus IN ('pending', 'rejected') THEN
    currentUser = 从 Session 获取当前用户
    IF currentUser IS NOT NULL AND currentUser.id = task.publisherId THEN
        → 返回完整任务详情（包含 auditStatus 和 auditRemark）
    ELSE
        → 返回 404（任务不存在或已删除）
    END IF
ELSE
    → 返回 404
END IF
```

**成功响应** `200 OK`（与现有 `/public/tasks/{id}` 结构一致，但待审核/已驳回状态额外包含审核字段）

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "id": 103,
    "title": "代拿药品",
    "status": "open",
    "auditStatus": "rejected",
    "auditRemark": "任务描述不够清晰，请补充取药具体信息",
    "publisherId": 1,
    "publisherName": "张三"
  }
}
```

**当前状态**：✅ 已实现（commit d122657）

#### 3.3.1 修改接口：管理员删除任务

```http
DELETE /api/admin/tasks/{taskId}
```

**认证**：需要（管理员）

**权限逻辑修改**：

```
Task task = taskDao.getById(taskId);
IF task IS NULL THEN
    → 返回 404
END IF
IF task.status != 'completed' THEN
    → 返回 400 或 409，msg: "只能删除状态为「已完成」的任务"
END IF
// 执行软删除
taskDao.updateStatus(taskId, "deleted");
```

**响应示例（失败时）**：

```json
{
  "code": 400,
  "msg": "只能删除状态为「已完成」的任务",
  "data": null
}
```

**当前状态**：✅ 已实现（commit d122657）
