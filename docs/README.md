## 阶段与阅读口径

| 阶段 | 内容 | 文档定位 |
| --- | --- | --- |
| 01 需求与基础设计 | 需求分析、前后端设计、数据库设计 | 早期基础方案，保留当时的范围与约定 |
| 02 核心交易闭环 | 基线接口、二手交易完成流程 | 基线契约及后续补记，需与增量文档合读 |
| 03 功能扩展 | 删除与终止、图片、管理员、评论及修改 | 各次扩展的接口约定与设计记录 |
| 04 联调测试与交付 | 联调修改、测试计划与记录、构建打包 | 集成、检查和交付材料；历史测试记录不代表本轮结果 |
| 05 交易双方评价 | 评价设计、实现与验收 | 已有实现记录，先读实现说明，再查原设计 |
| 06 消息中心 | 首版功能设计 | 当前下一阶段设计，尚无实现与验收记录 |
| 99 历史归档 | 原始旧版接口契约 | 历史对照资料 |

**阅读时注意：** 基础文档中的“管理员延期”“直接审核通过”“暂无图片／评价”等表述描述的是当时阶段，后续已存在相应增量。部分增量文档中的“后端尚未实现”也是当次交付记录，不能直接用来判断今天的实现状态。查现有行为时，结合后续实现说明与代码；本文档整理不重新判定每项功能的验收结果。

目录编号表示推进阶段，不按文件名日期机械排序。部分文件名日期与正文日期不一致，本次保留原名和正文日期，便于对照原有记录。

## 后续文档放置规则

- 现有功能的补充说明放回对应阶段目录，功能设计与实现验收记录放在一起。
- 新一轮功能迭代从 `07-功能名称` 开始编号，并在本目录补充进度与入口。
- 旧版备份放入 `99-历史归档`；已有历史文档仍保留原日期和版本，新增说明单独注明状态。
- 先更新本总目录，再补同阶段文档之间的相对链接，避免文档再次散落在 `docs/` 根目录。
