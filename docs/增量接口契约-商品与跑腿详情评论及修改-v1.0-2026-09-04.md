# 增量接口契约：商品与跑腿详情、评论及修改 v1.0

| 项目 | 内容 |
|---|---|
| 版本 / 日期 | v1.0 / 2026-09-28 |
| 基线 | `接口契约.md`、图片功能相关增量契约、管理员模块增量契约 |
| 交付边界 | 本次仅修改前端并新增本契约；没有修改 Java、数据库、已有契约或设计文档 |
| 接口状态 | 下述评论接口、编辑读取及保存接口均为新增约定，当前后端尚未实现，需后续对接 |
| 前端范围 | 商品和跑腿的详情页、发布页，以及它们共用的图片、评论、编辑组件 |

## 1. 界面与交互

- 桌面详情页：左侧固定单图，右侧文字和评论处于同一独立滚动区域。图片下方有上一张、数字切换和下一张按钮，首尾按钮禁用；点击图片打开大图对话框，支持左右方向键、Esc、关闭按钮及点击遮罩关闭，关闭后焦点回到图片。
- 窄屏（900px 及以下）采用图片在上、内容在下的单列页面滚动，保证小屏可读性，不将图片固定在文字上方遮挡内容。
- 发布页的图片区域同样只显示一张；另有“添加图片”“删除当前图片”按钮。沿用最多 3 张、每张 5 MB 及 JPG/PNG/GIF/WebP 限制，真实上传仍调用既有 `POST /api/upload/image`。保存字段仍为按显示顺序、逗号分隔的 `imageUrls`，空字符串表示清空图片。
- 上传中的本地 blob 地址只用于预览，绝不提交；上传未完成时禁止发布/保存并提示。上传失败移除对应预览并显示错误；删除上传中图片后，迟到的上传结果不得恢复该图片。
- 评论位于详情信息和操作区下方。所有已登录用户（包含发布者、买家、接单人、普通用户及管理员）均可评论和回复；游客可阅读，并通过登录入口参与。任何角色均只能删除自己发表的评论。
- 每页严格最多 10 条，回复作为一条独立评论计入分页，按发布时间正序、ID 正序排列。回复通过引用片段展示上下文，不使用展开无限子回复的形式绕过每页 10 条限制。
- 分页按钮位于本页评论末尾，超过 10 条时显示。发表后跳转至该评论所在页；删除最后一页的最后一条后自动返回最后一个有效页。
- 修改入口在详情页操作区：本人且商品 `on_sale` / 任务 `open` 时展示，其他身份或状态不展示。原订单不作为修改目标。
- 修改复用 `product-publish.jsp?productId={id}` / `task-publish.jsp?taskId={id}`；加载原稿及图片后才解锁表单，按钮为“保存修改”。保存失败保留输入，不创建新记录、不假报成功。
- 沿用现有审核机制：修改保存后重新待审核，前端成功后进入个人空间的对应发布记录页；“取消”返回原详情来源，地址经过同应用校验。

## 2. 通用响应和身份

继续使用 `{ "code": 0, "msg": "success", "data": ... }`。错误使用既有非零 `code` 与 `msg`，推荐同步返回相应 HTTP 状态。所有写操作与本人原稿读取携带 Session Cookie（`credentials: include`）；身份只能由 Session 推导，请求体不传发布者、作者或当前用户 ID。

下文 `{resource}` 仅允许 `products` 或 `tasks`，`{id}` 为对应商品或任务正整数 ID，评论在对应详情下隔离。

## 3. 评论接口（待对接）

### 3.1 分页读取

`GET /api/public/{resource}/{id}/comments?page=1&size=10`

资源的可见性沿用详情权限：公开审核通过的资源允许游客读取；不存在、已删除或无权查看返回 `404`。已售出、已接取、已完成但仍可见的资源允许继续交流。

`page` 为从 1 开始的正整数；本功能 `size` 固定为 10，非法参数返回 `400`。超出末页时返回空 `list` 和当前真实 `total`，供前端回退；不要用 `404` 表示空页。

成功 `data`：

```json
{
  "list": [
    {
      "id": 42,
      "authorId": 7,
      "authorName": "林同学",
      "content": "请问周五下午方便交接吗？",
      "createdAt": "2026-09-04 14:30:00",
      "replyTo": null
    },
    {
      "id": 43,
      "authorId": 8,
      "authorName": "周同学",
      "content": "可以，图书馆门口见。",
      "createdAt": "2026-09-04 14:35:00",
      "replyTo": {
        "id": 42,
        "authorName": "林同学",
        "content": "请问周五下午方便交接吗？",
        "deleted": false
      }
    }
  ],
  "total": 12,
  "page": 1,
  "size": 10
}
```

- `total` 是该资源下未删除评论与回复的总条数，必须是非负整数。`list` 最多 10 条，按 `createdAt ASC, id ASC` 稳定排序。
- `replyTo` 为所回复的直接父评论引用（允许回复另一条回复）；引用正文最多返回 160 字。不得要求父评论必须位于当前页。
- 父评论被删除时保留现有回复，返回 `replyTo: { "id": 42, "deleted": true }`，省略已删除正文；前端显示“原评论已删除”。
- `content`、昵称及引用都以纯文本呈现，前端转义，不执行 HTML。

### 3.2 发布评论 / 回复

`POST /api/{resource}/{id}/comments`

```json
{ "content": "请问还有其他配件吗？", "replyToId": null }
```

- `content` 去除两端空白后 1～1000 字；空白、超长返回 `400`。
- `replyToId` 省略或 `null` 表示新评论，正整数表示回复；必须属于当前资源且尚未删除，不能跨商品、跨任务或跨类型引用。
- 接口校验当前登录用户、账号状态及目标资源可见性。游客返回 `401`，无操作权限返回 `403`，资源不存在/不可见返回 `404`。父评论已删除/失效返回 `409`，提示改为新评论或重新选择回复对象。
- 成功 `data` 为 `{ "id": 44, "page": 2 }`，其中 `page` 是按同一排序、每页 10 条计算的新评论所在页。前端成功后才清空输入并刷新该页。
- 不接收客户端伪造的 `authorId` / `authorName` / `createdAt`。

### 3.3 删除本人评论

`DELETE /api/{resource}/{id}/comments/{commentId}`

无请求体；成功 `data` 为 `{ "id": 44 }`。

必须同时校验评论属于本资源且作者为当前 Session 用户；发布者、买家、接单人及管理员身份都不能越权删除其他用户的评论。非本人返回 `403`，无此评论或已删除返回 `404`，未登录返回 `401`。删除只影响此条评论，其他用户的回复保留，分页 `total` 减少。服务端必须在实际删除时校验作者条件，前端按钮隐藏不构成权限保障。

## 4. 修改接口（待对接）

### 4.1 读取本人原稿

`GET /api/products/{id}/edit` / `GET /api/tasks/{id}/edit`

只允许本人且当前业务状态可修改时读取；审核状态 `pending` / `approved` / `rejected` 不改变业务状态校验。返回值保留既有发布字段，不使用公开详情接口充当未审核原稿接口。

商品 `data` 示例：

```json
{
  "id": 21,
  "sellerId": 7,
  "status": "on_sale",
  "auditStatus": "approved",
  "title": "九成新高等数学教材",
  "description": "无缺页，少量笔记。",
  "category": "book",
  "condition": "good",
  "price": 18.5,
  "location": "图书馆门口",
  "contact": "微信：campus-example",
  "imageUrls": "/uploads/first.jpg,/uploads/second.jpg"
}
```

任务返回 `id`、`publisherId`、`status`、`auditStatus` 以及 `title`、`description`、`pickup`、`delivery`、`deadline`、`amount`、`contact`、`imageUrls`。`deadline` 为 `null` 或既有 `YYYY-MM-DD HH:mm:ss` 字符串。

未登录 `401`；非发布者 `403`；不存在/已删除 `404`；商品非 `on_sale` 或任务非 `open`、或存在未取消订单时 `409`。前端不得在原稿读取失败后将编辑流程降级为 `POST` 新建。

当前个人空间对待审核/驳回记录不开放详情入口；该模块本次不修改。若后续需从该模块直接编辑这些记录，应独立对接本人原稿入口，不能放宽公开详情对其他用户的审核可见性。

### 4.2 保存原商品 / 任务

`PUT /api/products/{id}`：完整提交 `title`、`description`、`category`、`condition`、`price`、`location`、`contact`、`imageUrls`，字段类型与 `POST /api/products` 一致。

`PUT /api/tasks/{id}`：完整提交 `title`、`description`、`pickup`、`delivery`、`deadline`、`amount`、`contact`、`imageUrls`，字段类型与 `POST /api/tasks` 一致。

- 标题去除两端空白后 1～80 字；价格/金额为有限非负数；枚举值沿用发布接口；任务取件、送达地点必填；时间格式沿用现有契约。
- 空 `imageUrls` 表示删除全部展示图片；已有图片 URL 可保留，新图片先走既有上传接口；不接收临时 blob/data URL。
- 身份与业务状态规则与读取原稿相同。保存时必须再次校验，不能信任进入编辑页时的状态。
- 商品的条件更新必须同时满足原 ID、当前卖家、未删除、`status=on_sale` 且无未取消购买订单；任务同理为原 ID、发布者、未删除、`status=open` 且无未取消接单记录。
- 与购买/接取并发发生时，需保证状态检查和实际写入原子化；若已经成交/接取，返回 `409`，不得覆盖原订单信息或修改已锁定价格、金额、地点等内容。
- 原 ID、发布者、创建时间和关联记录保持不变；更新修改时间，将 `auditStatus` 设为 `pending` 并清理旧审核意见，等待既有审核流程。
- 不允许请求体修改 `id`、身份、业务状态、审核状态或删除状态；不创建新商品、任务或订单。
- 成功 `data` 示例：`{ "id": 21, "status": "on_sale", "auditStatus": "pending" }`；任务 `status` 为 `open`。
- 错误状态：`400` 字段错误、`401` 未登录、`403` 非本人、`404` 不存在/已删除、`409` 已被购买/接取/完成或并发冲突。

## 5. 失败行为及联调检查

1. 图片地址为空显示主题占位，坏图可继续切换；详情一张图片、预览和大图均等比完整展示。
2. 评论读取失败显示独立错误与重试，原详情仍可浏览；不会伪造空列表、把评论写入 localStorage 或假报操作成功。
3. 评论 0 / 1 / 10 / 11 / 多页场景；末页删除回退；父评论删除保留回复；跨资源回复和非本人删除由接口拒绝。
4. 发布与回复期间禁止重复提交；失败保留正文与回复对象；翻页的旧请求不得覆盖新页。
5. 编辑回填含空字段、原图、时间；可删除/新增图片；取消回原详情；只发送原 ID 的 `PUT`，不发送 `POST` 新建。
6. 用他人 ID、已购买/已接取/已完成记录、无效 ID 或编辑中状态变化测试，均不能保存。
7. 保留原商品购买、任务接取/完成、删除与终止流程；非参与者不展示送达或终止处理按钮。现有公开任务详情未返回 `accepterId` 时，前端通过既有 `GET /api/me/tasks?type=accepted&page={page}&size=50` 分页确认本人接取身份，不新增后端实现。
8. 新接口未提供时，评论与编辑显示真实失败提示；本次前端使用隔离的模拟接口进行交互验证，不代表已完成后端持久化或服务端鉴权验收。
