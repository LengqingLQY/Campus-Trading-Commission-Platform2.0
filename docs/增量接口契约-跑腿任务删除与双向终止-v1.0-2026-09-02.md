# 增量接口契约：跑腿任务删除与双向终止 v1.0

| 项目 | 内容 |
|---|---|
| 版本 | v1.0 |
| 日期 | 2026-09-25 |
| 基线文档 | `docs/接口契约.md` |
| 变更性质 | 增量说明，不覆盖或修改基线文档 |
| 涉及前端 | `task-hall.jsp`、`task-detail.jsp`、`task-publish.jsp`、`profile-user.jsp` |
| 涉及 JS | `task.js`、`task-detail.js`、`task-publish.js`、`profile.js` |
| 需要后端新增 | 终止申请 4 个接口、数据库迁移 |


## 1. 变更目标

1. 跑腿任务详情页不再固定返回任务大厅，而是返回实际进入详情页的站内页面。
2. 发布者可以直接删除 `open` 和 `completed` 状态的任务；`accepted` 和 `delivered` 状态需走终止流程。
3. `accepted` 和 `delivered` 状态下，发布者或接取者任一方可以发起终止申请，另一方同意后任务回到 `open`。
4. 删除采用 `task.is_deleted` 字段进行软删除，不物理移除任务或关联订单。


## 2. 前端来源返回约定（无需后端接口）

### 2.1 跳转链接携带来源

- 进入 `task-detail.jsp` 的站内链接增加 `returnTo` 查询参数，值为来源页相对 web 根目录的地址。
- 示例：`task-detail.jsp?taskId=12&returnTo=profile-user.jsp%3FrecordTab%3Dpublished-tasks`
- 进入 `task-publish.jsp` 的链接同样携带 `returnTo`，发布成功后跳转回详情页并保留来源。

### 2.2 详情页返回处理

- `task-detail.jsp` 只接受当前 web 应用目录内的 `returnTo`，站外地址或非法地址回退到 `task-hall.jsp`。
- 没有 `returnTo` 时，使用同应用的 `document.referrer`；仍无法确定来源时回退到 `task-hall.jsp`。


## 3. 数据库增量设计

### 3.1 新增终止申请记录表

```sql
CREATE TABLE task_termination_request (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id       INTEGER NOT NULL REFERENCES task(id),
    requester_id  INTEGER NOT NULL REFERENCES user(id),
    reason        TEXT    NOT NULL,
    status        TEXT    NOT NULL DEFAULT 'pending'
                          CHECK (status IN ('pending', 'approved', 'rejected', 'withdrawn')),
    responder_id  INTEGER REFERENCES user(id),
    created_at    TEXT    NOT NULL DEFAULT (datetime('now', 'localtime')),
    resolved_at   TEXT
);

CREATE UNIQUE INDEX uq_task_pending_termination
ON task_termination_request(task_id)
WHERE status = 'pending';
```

### 3.2 调整 task_order 唯一约束

现有 `task_order.task_id UNIQUE` 会阻止任务终止后重新被接取。需要：

1. 重建 `task_order` 表，移除列级 `UNIQUE(task_id)`
2. 改为部分唯一索引：

```sql
CREATE UNIQUE INDEX uq_task_order_non_cancelled_task
ON task_order(task_id)
WHERE status <> 'cancelled';
```

**注意**：SQLite 不支持直接删除 UNIQUE 约束，需采用“新表复制数据 → 校验 → 原子替换”的迁移方式。


## 4. 删除（单方直接软删除）

### 4.1 允许删除的状态

| 任务状态 | 是否允许 | 说明 |
|---|---|---:|---|
| `open` | 是 | 删除待接取的任务 |
| `completed` | 是 | 隐藏已完成任务 |
| `accepted` | 否 | 存在进行中的接取，应走终止流程 |
| `delivered` | 否 | 存在进行中的接取，应走终止流程 |

### 4.2 请求

```http
DELETE /api/tasks/{id}
Cookie: JSESSIONID=...
```

### 4.3 成功响应

```json
{"code":0,"msg":"ok","data":{"id":12}}
```

### 4.4 失败响应

| HTTP | msg | 触发条件 |
|---:|---|---|
| `401` | 请先登录 | 未登录 |
| `403` | 只能删除自己发布的任务 | 非发布者 |
| `404` | 任务不存在 | 已不存在或已软删除 |
| `409` | 进行中的任务不能删除，请发起终止申请 | 状态为 `accepted` 或 `delivered` |


## 5. 双向终止申请

### 5.1 适用状态

`accepted`、`delivered`

### 5.2 状态流

```text
accepted / delivered
        │ 任一方发起
        ▼
原任务状态不变 + termination_request=pending
        ├─ 发起方撤回 ───────────────→ 原任务状态继续
        ├─ 另一方拒绝 ───────────────→ 原任务状态继续
        └─ 另一方同意 ─→ task_order=cancelled + task=open
```

约束：
- 同一任务同时最多存在一条 `pending` 申请。
- 待处理期间不得执行 `/deliver` 或 `/complete`。
- 发起人不能同意或拒绝自己的申请。

### 5.3 新增接口

| 功能 | 方法 | 路径 | 权限 |
|---|---|---|---|
| 发起终止申请 | POST | `/api/tasks/{id}/termination-request` | 登录，仅任务参与方 |
| 撤回终止申请 | DELETE | `/api/tasks/{id}/termination-request` | 登录，仅发起方 |
| 拒绝终止 | PUT | `/api/tasks/{id}/termination-request/reject` | 登录，仅另一方 |
| 同意终止 | PUT | `/api/tasks/{id}/termination-request/approve` | 登录，仅另一方 |

### 5.4 发起终止申请

```http
POST /api/tasks/{id}/termination-request
Content-Type: application/json

{"reason": "时间无法协调，希望终止本次跑腿"}
```

- `reason` 去除首尾空白后必须为 2～200 字。
- 仅 `accepted`、`delivered` 可发起。
- 已有 `pending` 申请返回 `409`。

成功返回：

```json
{"code":0,"msg":"ok","data":{"id":8,"status":"pending"}}
```

### 5.5 撤回终止申请

```http
DELETE /api/tasks/{id}/termination-request
```

- 仅发起方可操作。
- `pending → withdrawn`，任务和 `task_order` 状态不变。

### 5.6 拒绝终止申请

```http
PUT /api/tasks/{id}/termination-request/reject
```

- 仅非发起方操作。
- `pending → rejected`，任务和 `task_order` 状态不变。

### 5.7 同意终止申请

```http
PUT /api/tasks/{id}/termination-request/approve
```

- 仅非发起方操作。
- 事务内执行：
  1. `pending → approved`，写入 `responder_id/resolved_at`
  2. `task_order.status: accepted/delivered → cancelled`
  3. `task.status: accepted/delivered → open`

成功返回：

```json
{"code":0,"msg":"ok","data":{"taskId":12,"taskStatus":"open","orderId":5,"orderStatus":"cancelled"}}
```

### 5.8 错误响应

| HTTP | msg | 场景 |
|---:|---|---|
| `400` | `终止原因需为 2～200 字` | 原因不合法 |
| `401` | `请先登录` | 未登录 |
| `403` | `无权限操作该终止申请` | 非任务参与方 |
| `404` | `任务不存在` / `终止申请不存在` | 资源不存在 |
| `409` | `当前任务状态不允许终止` | 已完成或已终止 |
| `409` | `已有待处理的终止申请` | 重复发起 |


## 6. 修改现有接口

### 6.1 任务详情返回终止申请

`GET /api/public/tasks/{id}` 增加 `terminationRequest` 字段：

```json
{
  "id": 12,
  "status": "accepted",
  "terminationRequest": {
    "id": 3,
    "requesterId": 5,
    "requesterName": "鲍勃",
    "reason": "时间无法协调",
    "status": "pending",
    "createdAt": "2026-09-25 14:30:00"
  }
}
```

### 6.2 我的任务记录返回终止申请

`GET /api/me/tasks?type=accepted` 返回的进行中任务应包含 `terminationRequest` 字段。


## 7. 删除/终止后的查询表现

| 查询 | 删除后 | 终止后 |
|---|---|---|
| `GET /api/public/tasks` | ❌ 不出现 | ✅ 出现（`status=open`） |
| `GET /api/public/tasks/{id}` | ❌ `404` | ✅ 可查看，状态为 `open` |
| `GET /api/me/tasks?type=published` | ❌ 不出现 | ✅ 出现 |
| `GET /api/me/tasks?type=accepted` | ❌ 不出现 | ❌ 不出现 |
