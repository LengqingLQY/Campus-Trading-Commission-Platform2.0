# 前端新增接口协议 —— 二手交易闭环 v1.1

| 项目 | 内容 |
|---|---|
| 提出方 | 二手交易前端 |
| 日期 | 2026-08-29 |
| 依赖基线 | 《接口契约》v1.1 |
| 旧版备份 | `docs/backups/接口契约-v1.0-2026-08-29.md` |
| 涉及页面 | `product-detail.jsp`、`product-order.jsp`、`main.jsp` |

## 1. 为什么需要补充接口

现有 v1.0 契约的 `POST /api/products/{id}/buy` 只能生成购买记录，缺少购买后的订单详情、卖家交付和买家确认收货能力。前端无法仅依靠 `/api/me/products` 完成以下需求：

- 买家和卖家进入同一笔交易的角色化页面；
- 卖家确认已经线下交付商品；
- 买家在验货后确认收货并结束交易；
- 主界面待办栏准确区分“卖家待交付”和“买家待确认”。

因此增加以下 3 个接口。完整字段和错误约定已经同步进《接口契约》v1.1 §8.5～§8.7。

## 2. 新增接口清单

| 功能 | 方法 | 路径 | 权限 | 前端用途 |
|---|---|---|---|---|
| 查看二手订单 | GET | `/api/product-orders/{id}` | 仅买卖双方 | 渲染交易进度、对方资料和联系方式 |
| 卖家确认交付 | PUT | `/api/product-orders/{id}/deliver` | 仅卖家 | 将待办从“卖家待交付”推进为“买家待确认” |
| 买家确认收货 | PUT | `/api/product-orders/{id}/complete` | 仅买家 | 完成订单和商品交易 |

三个接口都使用现有 `HttpSession + JSESSIONID`，无需客户端传 `userId` 或角色。

本地联调时前端为 8080、后端为 8081。后端还需按《接口契约》§3.2.1 开启指定来源、允许凭证的 CORS，否则浏览器无法携带 `JSESSIONID` 完成订单鉴权。

## 3. 状态机

```text
product.status:
on_sale --购买--> sold --买家确认收货--> completed

product_order.status:
created --卖家确认交付--> delivered --买家确认收货--> completed
```

前端按钮规则：

| 当前身份 | 订单状态 | 页面主操作 |
|---|---|---|
| 卖家 | `created` | 确认商品已交付 |
| 买家 | `created` | 等待卖家交付（不可点击） |
| 卖家 | `delivered` | 等待买家确认（不可点击） |
| 买家 | `delivered` | 确认收到商品 |
| 买家或卖家 | `completed` | 只读显示交易已完成 |

## 4. 后端数据库改动提示

后端实现前需要迁移 `product_order`：

1. `status` 的 CHECK 允许值增加 `delivered`；
2. 新增可空字段 `delivered_at TEXT`；
3. `finished_at` 继续表示买家确认收货时间；
4. 迁移必须保留现有订单数据，不能通过删除 `app.db` 处理生产数据。

SQLite 不能直接修改已有 CHECK 约束，后端应采用“新表复制数据 → 校验 → 原子替换”的迁移方式，或使用项目统一的版本化迁移脚本。

## 5. 并发与事务要求

- 交付接口必须使用带状态条件的更新：`WHERE id=? AND seller_id=? AND status='created'`。
- 完成接口必须使用带状态条件的更新：`WHERE id=? AND buyer_id=? AND status='delivered'`。
- 完成接口更新 `product_order` 与 `product` 必须在同一事务中；任一步失败都回滚。
- 更新行数为 0 时返回 `409`，不能先查询再无条件更新。
- 订单详情中的成交价必须读取 `product_order.price`，不能读取可能变化的 `product.price`。

## 6. 前端验收用例

1. 买家购买在售商品后收到 `orderId`，跳转到 `product-order.jsp?orderId={orderId}`。
2. 非交易参与者请求订单详情得到 `403`。
3. 卖家看到“确认商品已交付”，买家在 `created` 状态只看到等待提示。
4. 卖家确认交付后，订单详情返回 `status='delivered'` 和非空 `deliveredAt`。
5. 买家确认收货后，订单返回 `completed`，商品详情返回 `product.status='completed'`。
6. 重复交付、交付前确认收货、重复确认收货均返回 `409`。
7. 主界面待办根据 `/api/me/products` 返回的 `orderStatus` 显示正确角色动作，并能跳回对应订单页。
