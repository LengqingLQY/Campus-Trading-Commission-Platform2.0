# 交易双方评价：实现与验收

> [文档总目录](../README.md) · 05-交易双方评价

本次实现以《增量功能设计-交易双方评价-v1.0》及现有前端字段为准。

## 数据库与启动

- 新增 `rating` 表、两组订单评价唯一索引及被评价人身份索引。评分限定整数 1～5；每条评价恰好关联一种订单。
- 买家评卖家、发布者评接单者，均计入对方 `seller` 栏；反向评价计入对方 `buyer` 栏。平均分实时聚合，前端保留一位小数。
- 后端启动会执行 `backend-java/src/main/resources/db/migrations/001-rating.sql`，仅增加表和索引，可重复运行，不重置旧数据。
- 也可在仓库根目录执行 `python backend/db/migrate_db.py --db 现有数据库路径`。脚本要求数据库已存在。
- 全新环境使用 `python backend/db/init_db.py` 创建基础数据库和演示数据。该命令会重建数据库，仅用于首次创建或主动重置；已有库使用迁移命令。
- 新建库的 `schema.sql` 同步包含评价结构，初始化时先删除评价子表再处理订单。

## 接口与前端字段

接口均使用 `Result{code,msg,data}`；除用户公开评分外，需要 session 登录。

| 接口 | 行为 |
| --- | --- |
| `POST /api/product-orders/{id}/rating` | 订单双方为对方评分，请求 `{"stars":5}` |
| `POST /api/task-orders/{id}/rating` | 跑腿订单双方为对方评分 |
| `GET /api/task-orders/{id}` | 双方可读订单标题、双方昵称、`viewerRole`、`myRatingStars` 和 `counterpartyRating` |
| `GET /api/me/rating-orders?state=all&page=1&size=20` | 统一分页读取两类已完成订单；`state=pending` 仅返回本人尚未评价的订单 |
| `GET /api/public/users/{id}/rating` | 返回 `userId、username、avatarUrl、buyer、seller`；不暴露账号或联系方式 |

订单不存在返回 404，未登录 401，非参与者 403，非 JSON 整数或越界评分 400，未完成、已终止、重复评价返回 409。客户端传入的评价对象及身份不参与计算。并发重复提交只有一条成功，另一条返回 409。

空评分明确返回 `{"average":null,"count":0}`。二手订单详情补充 `myRatingStars` 和 `counterpartyRating`；未评价时星级为 null。

商品列表与详情返回 `sellerRatingAverage、sellerRatingCount`，任务列表与详情返回 `publisherRatingAverage、publisherRatingCount`；使用聚合 JOIN，一次查询返回整页评分。任务继续使用 `amount、pickup、delivery`。

任务详情对本次订单参与者返回 `orderId` 和 `viewerRole=publisher|accepter`，前端不再遍历接取记录推断身份。已完成任务或商品软删除后，订单详情和评价记录仍可访问。评价记录每项的对方角色字段使用现有前端名称 `counterpartRole`。

前端修复了评价按钮事件对象误传、跑腿金额地点字段误用，并提供待评价筛选、翻页和保留筛选页码的返回入口。订单页提交成功后重新读取订单与对方评分，已完成订单也展示对方现有信誉。

## 自动化验证

在仓库根目录运行：

```powershell
.\mvnw.cmd package -B
node --test web/tests/*.test.js
python backend/db/test_db.py
```

`RatingIntegrationTest` 使用临时 SQLite，覆盖启动迁移、重复迁移、四个评价方向、评分类型和边界、权限、状态、并发重复提交、软删除历史、分页筛选、聚合展示及公开资料范围。不会连接正式 `app.db`。

前端脚本测试覆盖选择星级、请求期间禁用按钮、接口失败提示、成功后刷新、平均分格式、翻页筛选和来源保留。浏览器布局及键盘交互交由人工验收。

## 手动页面验收

1. 买卖双方分别登录同一笔已完成二手订单，各提交一次评分；确认再次进入显示已评价，公开信誉的对应栏目更新。
2. 跑腿发布者和接单者分别登录，使用详情的订单入口完成双向评价；进行中的订单应能查看对方已有评分。
3. 删除已完成任务或商品后，从个人空间“待评价 / 评价记录”进入订单，确认仍能查看和评价。
4. 在超过 20 笔记录时翻到第二页，切换待评价筛选，并检查从订单返回时筛选和页码保留。
5. 核对首页与任务大厅的跑腿费用及取送地点；用 Tab、方向键选择星级，检查焦点、错误提示和页面布局。
