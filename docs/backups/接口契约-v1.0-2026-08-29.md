# 校园跑腿交易平台 —— 用户端接口契约

| 项目 | 内容 |
|---|---|
| 版本 | v1.0 |
| 编写日期 | 2026-08-27 |
| 适用范围 | 当前阶段普通用户端，管理员功能延期 |
| 对应前端 | `web/index.jsp`、`register.jsp`、`task-*.jsp`、`secondhand.jsp`、`product-*.jsp`、`profile-user.jsp` |
| 对应后端 | `backend-java` Spring Boot REST 服务 |
| 对应数据库 | `backend/db/schema.sql` 的 `user`、`task`、`product`、`task_order`、`product_order` |
| 服务地址 | `http://localhost:8081` |
| 接口数量 | 17 个（账号 5、任务 6、商品 4、个人空间 2） |

> 本文档是前后端联调的唯一接口基线。字段名、枚举值或响应结构需要变更时，先修改本文档，再修改代码。

## 1. 范围与本阶段决策

### 1.1 本阶段包含

- 注册、登录、退出和当前用户资料的查看/修改。
- 跑腿任务的列表、详情、发布、接取、送达和完成。
- 二手商品的列表、详情、发布和购买。
- 个人空间中的我发布、我接取、我购买记录。
- 任务和商品的关键词检索、按时间排序、按金额/价格排序。

### 1.2 管理员功能延期

以下内容不属于本版本接口契约，也不作为当前验收条件：

- 管理员登录后的管理页面；
- 任务/商品审核、驳回和审核列表；
- 任务软删除、商品下架；
- 用户列表、修改他人资料和重置密码；
- 所有 `/api/admin/**` 路径及管理员权限拦截器。

`web/profile-admin.jsp` 保留为后续视觉稿，不接入当前路由。数据库中的 `user.role=admin`、`audit_status`、`is_deleted`、`deleted_by`、`deleted_at` 仍保留，当前接口不允许普通用户修改，也不依赖管理员接口。

### 1.3 无管理员时的发布规则

当前版本没有审核接口。普通用户通过 `POST /api/tasks` 或 `POST /api/products` 创建数据时，服务端必须显式写入 `audit_status='approved'`，使内容可以按公开视图正常展示；业务状态分别为 `open` 和 `on_sale`。

数据库默认值 `pending` 以及 `pending/rejected` 数据用于兼容已有演示数据和后续管理员模块。公开列表和详情仍必须使用 `v_public_task`、`v_public_product`，只返回 `audit_status=approved AND is_deleted=0` 的数据。

## 3. 通用约定

### 3.1 URL、请求和响应

- 基础地址：`http://localhost:8081`；接口路径不包含项目上下文路径。
- 请求体使用 `application/json; charset=UTF-8`，响应统一为 UTF-8 JSON。
- 成功返回 HTTP `200`；失败返回对应的 `4xx/5xx`，不把业务失败统一包装成 HTTP `200`。
- 所有响应使用统一结构：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {}
}
```

`code=0` 表示成功；失败时 `code` 与 HTTP 状态码一致，`data` 固定为 `null`。成功但没有业务数据时 `data` 也为 `null`。

### 3.2 登录态

- 使用 `HttpSession + JSESSIONID` Cookie。
- 登录成功后服务端将当前用户放入 session；浏览器后续请求必须携带 Cookie。
- 退出调用 `POST /api/logout`，服务端销毁 session。
- session 默认 30 分钟无操作过期；过期调用登录接口时返回 `401`。
- 当前用户身份只从 session 取得，客户端不得通过 `userId` 参数指定操作者。
- 当前版本没有“记住我”和找回密码接口；页面中的相应控件不进入本契约。

### 3.3 字段、时间和金额

- 接口字段使用驼峰命名，数据库字段使用下划线命名，例如 `createdAt` 对应 `created_at`。
- 时间统一为字符串 `YYYY-MM-DD HH:MM:SS`，例如 `2026-08-27 14:30:00`。空的可选时间传 `null`。
- `datetime-local` 的 `2026-08-27T14:30` 提交前转换为 `2026-08-27 14:30:00`。
- `amount`、`price` 单位为元，JSON 中传非负数字；前端展示统一保留两位小数。
- 密码只在请求中出现，任何响应都不得返回 `passwordHash` 或明文密码。

### 3.4 分页和排序

列表接口统一支持：

| 参数 | 类型 | 默认值 | 规则 |
|---|---|---:|---|
| `page` | integer | 1 | 从 1 开始，`page<1` 返回 400 |
| `size` | integer | 10 | 最大 50，超过上限返回 400 |

列表响应统一为：

```json
{
  "list": [],
  "total": 0,
  "page": 1,
  "size": 10
}
```

排序参数只允许白名单值；非法值按对应接口默认值处理：

| 接口 | 可选值 | 默认值 |
|---|---|---|
| 任务列表 | `time_desc`、`time_asc`、`amount_desc`、`amount_asc` | `time_desc` |
| 商品列表 | `time_desc`、`time_asc`、`price_desc`、`price_asc` | `time_desc` |

## 4. 数据字典

数据库和接口传英文码，中文只由前端显示层映射。

| 字段 | 允许值 | 页面显示 |
|---|---|---|
| `task.status` | `open` | 待接取 |
|  | `accepted` | 已接取 |
|  | `delivered` | 已送达 |
|  | `completed` | 已完成 |
| `product.status` | `on_sale` | 在售 |
|  | `sold` | 已售出 |
| `task_order.status` | `accepted`、`delivered`、`completed`、`cancelled` | 接单中、已送达待确认、已完成、已取消 |
| `product_order.status` | `created`、`completed`、`cancelled` | 已成交、已完成、已取消 |
| `product.category` | `book`、`electronic`、`daily`、`clothing`、`sports`、`other` | 图书教材、电子数码、生活日用、服饰鞋帽、运动户外、其他 |
| `product.condition` | `new`、`almost_new`、`good`、`fair` | 全新、几乎全新、成色良好、有使用痕迹 |

`auditStatus` 及 `auditRemark` 仅在个人记录或本人详情中按需返回；当前用户创建的数据固定为 `approved`，普通公开列表不返回审核字段。

## 6. 账号接口

### 6.1 注册

`POST /api/register`

请求体：

```json
{
  "account": "alice2",
  "password": "alice123",
  "username": "小艾",
  "qq": "10004",
  "wechat": "wx_xiaoai",
  "phone": "13800138000"
}
```

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| `account` | string | 是 | 非空，不能重复 |
| `password` | string | 是 | 非空，长度至少 6 |
| `username` | string | 是 | 非空 |
| `qq`、`wechat`、`phone` | string | 否 | 可为空；不做验证码、真实性和格式校验 |

服务端固定 `role=user`，忽略请求中的 `role`、`status`、`passwordHash` 等字段。

成功：

```json
{"code":0,"msg":"ok","data":{"id":5}}
```

失败：`400` 参数缺失或密码过短；`409` 账号已存在。

### 6.2 登录

`POST /api/login`

请求体：

```json
{"account":"alice","password":"alice123"}
```

成功后写入 session，并返回：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "id": 2,
    "account": "alice",
    "username": "爱丽丝",
    "role": "user"
  }
}
```

账号不存在、密码错误或账号不可用统一返回 `401` 和“账号或密码错误”。当前版本只验收 `role=user` 的普通用户闭环；数据库中保留的 `admin` 账号属于后续管理员模块的兼容数据。

### 6.3 退出

`POST /api/logout`

无需请求体。成功返回：

```json
{"code":0,"msg":"ok","data":null}
```

### 6.4 查看当前用户资料

`GET /api/users/me`

成功返回：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "id": 2,
    "account": "alice",
    "username": "爱丽丝",
    "qq": "10001",
    "wechat": "wx_alice",
    "phone": "13800000001",
    "role": "user",
    "createdAt": "2026-08-25 18:22:38",
    "updatedAt": "2026-08-25 18:22:38"
  }
}
```

未登录返回 `401`。

### 6.5 修改当前用户资料

`PUT /api/users/me`

请求体字段均可选，但至少提供一个需要修改的字段：

```json
{
  "username": "新昵称",
  "qq": "10002",
  "wechat": "",
  "phone": "13900000001",
  "oldPassword": "alice123",
  "newPassword": "alice456"
}
```

规则：

- `username`、`qq`、`wechat`、`phone` 可独立修改；空字符串表示清空联系方式。
- 修改密码时 `oldPassword` 和 `newPassword` 必须同时提供，旧密码不正确返回 `401`，新密码少于 6 位返回 `400`。
- `account`、`role`、`status` 不可修改；请求中出现时忽略。

成功返回 `data=null`；未登录返回 `401`。

## 7. 跑腿任务接口

### 7.1 任务列表

`GET /api/public/tasks`

查询参数：`keyword`（可选，匹配 `title` 和 `description`）、`sort`、`page`、`size`。

返回的列表项至少包含：

```json
{
  "id": 1,
  "title": "帮取快递",
  "description": "菜鸟驿站取个箱子",
  "pickup": "三号门菜鸟驿站",
  "delivery": "12栋305",
  "deadline": "2026-08-27 18:00:00",
  "amount": 5.0,
  "status": "open",
  "publisherId": 2,
  "publisherName": "爱丽丝",
  "createdAt": "2026-08-25 18:22:38"
}
```

列表不返回 `contact`、`auditStatus`、`auditRemark`、`isDeleted`。仅查询公开视图，不支持 `status`、地点、金额区间等额外筛选。

### 7.2 发布任务

`POST /api/tasks`

请求体：

```json
{
  "title": "帮取快递",
  "description": "菜鸟驿站取个箱子",
  "pickup": "三号门菜鸟驿站",
  "delivery": "12栋305",
  "deadline": "2026-08-27 18:00:00",
  "amount": 5.0,
  "contact": "QQ 123456"
}
```

| 字段 | 必填 | 规则 |
|---|---:|---|
| `title`、`pickup`、`delivery` | 是 | 非空 |
| `description`、`contact` | 否 | 缺省按空字符串保存 |
| `deadline` | 否 | `null` 或 `YYYY-MM-DD HH:MM:SS` |
| `amount` | 否 | 非负，缺省为 `0` |

`publisherId` 从 session 取得，不接受请求中的用户 id。当前版本写入 `auditStatus='approved'`、`status='open'`。

成功：`{"code":0,"msg":"ok","data":{"id":13}}`。

失败：`400` 参数或时间格式错误；`401` 未登录。

### 7.3 任务详情

`GET /api/public/tasks/{id}`

成功返回任务详情，字段为列表项字段加 `contact`、`updatedAt`。已登录且为发布者本人时，可额外返回 `auditStatus`、`auditRemark`；其他请求者不返回审核字段。任务不存在、未审核或已软删除时返回 `404`。

### 7.4 接取任务

`POST /api/tasks/{id}/accept`

无请求体。服务端必须在同一事务中完成：

1. 校验任务为公开的 `status=open`，且当前用户不是发布者；
2. 将 `task.status` 更新为 `accepted`；
3. 插入一条 `task_order`，其 `status=accepted`。

成功：`{"code":0,"msg":"ok","data":{"orderId":5}}`。

失败：`401` 未登录；`403` 接取自己的任务；`404` 任务不存在或不可见；`409` 已被接取或状态不允许。

### 7.5 标记已送达

`PUT /api/tasks/{id}/deliver`

无请求体，仅 `task_order.accepterId` 对应的本人可调用。事务内将：

- `task.status: accepted -> delivered`；
- `task_order.status: accepted -> delivered`；
- 写入 `deliveredAt`。

成功 `data=null`；未登录返回 `401`，非接单方返回 `403`，任务不存在返回 `404`，状态不正确返回 `409`。

### 7.6 确认完成

`PUT /api/tasks/{id}/complete`

无请求体，仅发布者本人可调用。为兼容当前页面的简化闭环，允许从 `accepted` 或 `delivered` 进入完成：

- `task.status -> completed`；
- `task_order.status -> completed`；
- 写入 `finishedAt`。

成功 `data=null`；未登录返回 `401`，非发布者返回 `403`，任务不存在返回 `404`，状态不允许返回 `409`。当前版本没有管理员强制完成路径。

## 8. 二手商品接口

### 8.1 商品列表

`GET /api/public/products`

查询参数：`keyword`（匹配 `title` 和 `description`）、`sort`、`page`、`size`。

列表项至少包含：

```json
{
  "id": 1,
  "title": "高数教材",
  "description": "同济版，无笔记",
  "category": "book",
  "condition": "almost_new",
  "price": 15.0,
  "location": "图书馆一楼",
  "status": "on_sale",
  "sellerId": 2,
  "sellerName": "爱丽丝",
  "createdAt": "2026-08-25 18:22:38"
}
```

列表不返回 `contact`、`auditStatus`、`auditRemark`、`isDeleted`；当前版本不传 `category` 过滤参数，页面分类按钮为占位控件。

### 8.2 发布商品

`POST /api/products`

请求体：

```json
{
  "title": "高数教材",
  "description": "同济版，无笔记",
  "category": "book",
  "condition": "almost_new",
  "price": 15.0,
  "location": "图书馆一楼",
  "contact": "微信 wx_alice"
}
```

| 字段 | 必填 | 规则 |
|---|---:|---|
| `title` | 是 | 非空 |
| `description`、`location`、`contact` | 否 | 缺省按空字符串保存 |
| `category` | 否 | 缺省 `other`，且必须为数据字典中的值 |
| `condition` | 否 | 缺省 `good`，且必须为数据字典中的值 |
| `price` | 否 | 非负，缺省 `0` |

`sellerId` 从 session 取得；当前版本写入 `auditStatus='approved'`、`status='on_sale'`。

成功：`{"code":0,"msg":"ok","data":{"id":9}}`。

失败：`400` 标题为空、价格为负或枚举值非法；`401` 未登录。

### 8.3 商品详情

`GET /api/public/products/{id}`

成功返回列表项字段加 `contact`、`updatedAt`；卖家本人可额外看到 `auditStatus`、`auditRemark`。商品不存在、未审核或已软删除时返回 `404`。

### 8.4 购买商品

`POST /api/products/{id}/buy`

无请求体。服务端必须在同一事务中完成：

1. 校验商品为公开的 `status=on_sale`，且当前用户不是卖家；
2. 将 `product.status` 更新为 `sold`；
3. 插入一条 `product_order`，其 `price` 保存购买瞬间的价格快照。

成功：`{"code":0,"msg":"ok","data":{"orderId":3}}`。

失败：`401` 未登录；`403` 购买自己的商品；`404` 商品不存在或不可见；`409` 已售出或状态不允许。

## 9. 个人空间接口

### 9.1 我的任务

`GET /api/me/tasks?type=published&page=1&size=10`

`type` 只允许：

| 值 | 返回内容 |
|---|---|
| `published`（默认） | 当前用户发布的任务，包含审核字段；存在接单记录时附 `accepterId`、`accepterName`、`orderStatus` |
| `accepted` | 当前用户接取的任务，附 `orderId`、`orderStatus`、`acceptTime`、`deliveredAt`、`finishedAt` |

查询条件必须使用 session 中的用户 id。发布记录可看到自己的 `pending/rejected` 历史数据，但不得看到他人的未审核数据；当前版本新建记录为 `approved`。

### 9.2 我的商品

`GET /api/me/products?type=published&page=1&size=10`

`type` 只允许：

| 值 | 返回内容 |
|---|---|
| `published`（默认） | 当前用户发布的商品，已售出时附 `buyerId`、`buyerName`、`dealPrice`、`orderStatus`、`buyTime` |
| `bought` | 当前用户购买的商品，附 `orderId`、`sellerId`、`sellerName`、`dealPrice`、`orderStatus`、`buyTime` |

不存在其他单独的 `/api/me/orders` 接口；订单信息随上述两个资源返回。

## 10. 权限、状态和错误

### 10.1 权限矩阵

| 操作 | 游客 | 已登录普通用户 | 资源所有者 |
|---|:---:|:---:|:---:|
| 浏览公开任务/商品列表和详情 | ✅ | ✅ | ✅ |
| 注册、登录 | ✅ | — | — |
| 发布任务/商品 | ❌ | ✅ | — |
| 接取任务 | ❌ | ✅ | 自己发布的不可接取 |
| 购买商品 | ❌ | ✅ | 自己发布的不可购买 |
| 标记已送达 | ❌ | ✅ | 仅该任务接单方 |
| 确认完成 | ❌ | ✅ | 仅该任务发布者 |
| 查看/修改自己的资料 | ❌ | ✅ | ✅ |
| 查看自己的未审核记录 | ❌ | ✅ | ✅ |

前端按钮隐藏只改善体验，不构成权限控制；所有写接口都必须在后端再次校验身份和状态。

### 10.2 状态流转

```text
任务：open --接取--> accepted --接单方送达--> delivered --发布者确认--> completed
                         \----------------发布者直接确认----------------/

商品：on_sale --购买--> sold
```

任务接取和商品购买必须使用“带状态条件的 UPDATE + INSERT”事务，并依赖 `UNIQUE(task_order.task_id)`、`UNIQUE(product_order.product_id)` 做数据库兜底，避免并发重复操作。

### 10.3 错误码

| code | 含义 | 当前阶段典型场景 |
|---:|---|---|
| `0` | 成功 | 请求处理完成 |
| `400` | 参数错误 | 必填项为空、金额为负、枚举或时间格式非法 |
| `401` | 未登录/凭证错误 | session 过期、账号密码错误 |
| `403` | 无权限 | 接取/购买自己的资源、非接单方送达、非发布者完成 |
| `404` | 资源不存在或不可见 | id 不存在、未审核、已软删除 |
| `409` | 状态冲突 | 重复账号、重复接取、重复购买、状态不允许 |
| `500` | 服务器错误 | 未预期异常或数据库错误 |

错误示例：

```json
{"code":409,"msg":"任务已被接取","data":null}
```

## 11. 前端暂不应调用的接口和字段

下列内容在页面上可能存在文字或视觉占位，但不属于当前接口契约：

| 页面现象 | 当前处理 |
|---|---|
| 管理员个人空间、审核/删除/用户管理 | 暂不实现，不调用 `/api/admin/**` |
| “提交审核”“等待管理员审核”文案 | 当前接口直接发布为 `approved`；联调时按本契约调整文案或状态展示 |
| 任务大厅“待审核”等状态筛选 | 只显示状态，不传 `status` 查询参数 |
| 商品分类筛选 | 只提交商品分类字段，不传 `category` 查询参数 |
| 登录“记住我”、忘记密码 | 当前无接口，不保存长期登录凭证 |
| 注册确认密码、使用规范勾选、发布确认勾选 | 前端提交前校验，不落库；接口只接收业务字段 |
| 图片、收藏、评价、聊天、支付、通知 | 当前没有对应表和接口 |
