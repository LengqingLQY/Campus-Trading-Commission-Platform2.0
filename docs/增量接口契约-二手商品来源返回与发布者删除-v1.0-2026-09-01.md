# 增量接口契约：二手商品来源返回与发布者删除

| 项目 | 内容 |
|---|---|
| 版本 | v1.0 |
| 日期 | 2026-09-25 |
| 基线文档 | `docs/接口契约.md` |
| 变更性质 | 增量说明，不覆盖或修改基线文档 |
| 涉及前端 | `product-detail.jsp`、`secondhand.jsp`、`main.jsp`、`profile-user.jsp`、`product-order.jsp` |
| 需要后端新增 | `DELETE /api/products/{id}` |

## 1. 变更目标

1. 商品详情页不再固定返回二手商品列表，而是返回实际进入详情页的站内页面。
2. 商品发布者可以删除自己的商品；非发布者不能看到可用的删除操作，后端仍必须独立校验身份与所有权。
3. 删除采用现有 `product.is_deleted`、`deleted_by`、`deleted_at` 字段进行软删除，不物理移除商品或关联订单。

## 2. 前端来源返回约定（无需后端接口）

- 进入 `product-detail.jsp` 的站内链接增加 `returnTo` 查询参数，值为来源页相对 web 根目录的地址，可包含查询参数和锚点。
- 示例：

```text
product-detail.jsp?productId=12&returnTo=profile-user.jsp%3FrecordTab%3Dpublished-products%23profile-records
```

- 详情页只接受当前 web 应用目录内的 `returnTo`，站外地址或非法地址必须回退到 `secondhand.jsp`，防止开放重定向。
- 没有 `returnTo` 时，可使用同应用的 `document.referrer`；仍无法确定来源时回退到 `secondhand.jsp`。
- 从个人空间进入时，`returnTo` 应包含 `recordTab`，返回后恢复原记录标签。
- 删除成功后的跳转同样使用已校验的来源地址。

## 3. 新增接口：发布者删除商品

### 3.1 请求

```http
DELETE /api/products/{id}
Cookie: JSESSIONID=...
```

- 需要登录。
- 不需要请求体。
- `id` 为正整数商品编号。
- 当前用户必须从服务端 Session 获取；不得接受前端传入的 `sellerId`、`deletedBy` 等身份字段。

### 3.2 允许删除的状态

| 商品状态 | 是否允许 | 说明 |
|---|---:|---|
| `on_sale` | 是 | 删除在售发布信息 |
| `sold` | 否 | 存在进行中的交易，返回 `409`，避免卖家删除交易入口 |
| `completed` | 是 | 隐藏发布信息，但必须保留已经完成的订单记录 |

### 3.3 成功响应

HTTP `200`

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "id": 12
  }
}
```

### 3.4 失败响应

| HTTP / code | msg 建议值 | 触发条件 |
|---:|---|---|
| `400` | `商品编号不合法` | `id` 不是合法正整数 |
| `401` | `请先登录` | Session 中没有当前用户 |
| `403` | `只能删除自己发布的商品` | 商品存在，但当前用户不是发布者 |
| `404` | `商品不存在` | 商品不存在或已经被软删除；重复删除也返回此结果 |
| `409` | `交易进行中的商品不能删除` | 商品状态为 `sold` |

失败时继续使用统一响应结构，`data` 为 `null`。

## 4. 后端处理约束

1. Service 先按原表查询商品，判断存在性、`is_deleted`、发布者和业务状态。
2. 仅在 `seller_id = 当前用户`、`is_deleted = 0` 且 `status IN ('on_sale', 'completed')` 时执行软删除。
3. 更新字段：

```sql
UPDATE product
SET is_deleted = 1,
    deleted_by = :currentUserId,
    deleted_at = datetime('now', 'localtime'),
    updated_at = datetime('now', 'localtime')
WHERE id = :productId
  AND seller_id = :currentUserId
  AND is_deleted = 0
  AND status IN ('on_sale', 'completed');
```

4. 更新行数为 `0` 时必须重新确认并发后的实际状态，返回 `403`、`404` 或 `409`，不能误报成功。
5. 不删除 `product_order`，不修改已完成订单的状态、成交价、买卖双方或时间字段。

## 5. 删除后的查询表现

| 查询 | 预期结果 |
|---|---|
| `GET /api/public/products` | 不再出现被删商品 |
| `GET /api/public/products/{id}` | 返回 `404` |
| `GET /api/me/products?type=published` | 不再出现被删商品 |
| `GET /api/me/products?type=bought` | 已产生订单时仍保留买家交易记录 |
| `GET /api/product-orders/{orderId}` | 已产生订单时仍可读取订单，不受商品软删除影响 |

## 6. 前端交互验收

1. 从个人空间的“我上架的商品”进入详情，顶部返回和底部返回均回到个人空间的同一标签。
2. 从二手列表、发现首页、交易页进入详情，返回到各自来源页；直接打开详情链接时返回二手列表。
3. 当前用户不是发布者时，不渲染删除按钮。
4. 发布者查看 `on_sale` 或 `completed` 商品时显示“删除商品”，删除前展示不可恢复提示。
5. 发布者查看 `sold` 商品时显示禁用的“交易中不可删除”。
6. 删除请求成功后使用安全来源地址离开详情页；请求失败时停留当前页并显示后端错误信息。
